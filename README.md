# Excel Automation & Power Query — Monthly Insurance Claims Reporting

**Tools:** Microsoft Excel · Power Query (M) · PivotTables · PivotCharts  
**Reporting period:** January–April 2026  
**Dataset:** Synthetic claims data for a fictional Australian insurer

## 1. Business Problem

Monthly insurance claims data arrived as separate CSV files containing inconsistent formats, combined fields, missing or unconfirmed payment amounts, and a duplicate record. Preparing each file manually would create repetitive work and increase the risk of reporting errors.

**Objective:** Build a repeatable Excel reporting workflow that consolidates monthly files, applies consistent data transformations and quality checks, and updates financial reporting when a new CSV is added.

## 2. Solution — Data Transformation, Validation & Excel Automation

Developed a folder-based **Power Query** workflow connected to an Excel reporting workbook.

### Data ingestion and transformation

- **Consolidated** monthly CSV files into one structured reporting dataset.
- **Standardised** claim types, state abbreviations, payment methods and inconsistent text formatting.
- **Separated** composite region/location and handler/contact fields into usable columns.
- **Converted** payment amounts to a currency data type and payment dates to dates.
- **Retained** source filenames to support traceability.

### Data cleansing, validation and quality assurance

- Preserved the original payment text before converting amounts for financial reporting.
- Classified payment exceptions using a `Payment_Status` column:

  | Status | Meaning |
  |---|---|
  | `Amount Recorded` | Numeric payment available |
  | `Missing Amount` | Payment value unavailable |
  | `To Be Confirmed` | Original payment value was `TBC` |
  | `Zero Payment - Review` | Recorded payment equals zero |

- Investigated a repeated February Claim ID and excluded **one confirmed accidental duplicate** from the reporting output.
- Reconciled monthly record counts and payment totals with the original synthetic CSV files, accounting for the duplicate and non-numeric payment values.

See [Data Quality & Financial Reconciliation](docs/validation.md) for the supporting checks and assumptions.

### Business reporting

Built three Excel worksheets to present the transformed data and monthly financial results:

| Worksheet | Purpose |
|---|---|
| `Claims_Data` | Cleaned, consolidated Excel Table |
| `Monthly_Summary` | PivotTable showing monthly record counts and recorded payments |
| `Claims_Dashboard` | PivotChart showing monthly recorded payments |

### Refresh-based automation

**Monthly CSV → Source folder → Power Query → Excel Table → PivotTable → PivotChart**

Tested the workflow by adding an April 2026 CSV to the source folder and selecting **Data → Refresh All**. The workbook incorporated the new month without rebuilding its transformations, PivotTable or chart.

**Automation scope:** The refresh is manually triggered in Excel; it is not a scheduled or unattended pipeline.

## 3. Verified Reporting Results

| Payment month | Claim records | Recorded payments (AUD) |
|---|---:|---:|
| January 2026 | 45 | $471,777.28 |
| February 2026 | 50 | $483,390.95 |
| March 2026 | 55 | $496,097.32 |
| April 2026 | 53 | $502,794.99 |
| **Total** | **203** | **$1,954,060.54** |

**Reconciliation:** The four source files contained **204 rows**. Removing one confirmed February duplicate left **203 reporting records**. The initial January–March report contained 150 records; the April refresh added 53 more.

**Business interpretation:** Recorded payments increased each month, but these figures alone do not establish worsening claims performance. The dataset does not include the premiums, exposure or claims valuation information needed for profitability or loss-ratio analysis.

## 4. How to Reproduce

1. Download the repository and place the four synthetic CSV files from `data/raw/` together in one local folder.
2. Open `report/Southern_Lantern_Claims_Report.xlsx` in Microsoft Excel.
3. Go to **Data → Queries & Connections**, open the main claims query, then select **Home → Advanced Editor**.
4. Change the folder path inside `Folder.Files(...)` to the local CSV folder. For example:

   ```powerquery
   Source = Folder.Files("C:\Path\To\Your\Monthly_Claims_CSVs"),
   ```

5. Select **Data → Refresh All** and confirm that `Claims_Data`, `Monthly_Summary` and `Claims_Dashboard` contain January–April results.
6. Compare the monthly counts and totals with Section 3 and [the validation log](docs/validation.md).

**Note:** `power-query/Claims_Transformations.m` documents the main transformations. It references the `Transform File` and `Sample File` helper objects generated by Power Query's folder-combine process; these dependencies are held in the Excel workbook. The published script uses a generic source path, while the workbook's connection must be updated for another computer.

## 6. Reporting Limitations

- **Financial scope:** Results represent recorded payments, not incurred liabilities or underwriting profitability.
- **Incomplete amounts:** Blank and `TBC` payments are excluded from numeric totals; zero payments remain included and flagged.
- **Reporting period:** Four months are insufficient to establish long-term trends.
- **Synthetic dataset:** All data is fictional and does not represent an actual insurer's performance.
